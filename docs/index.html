Capabilities

Everything a working agent needs — in one process

No orchestration server, no cloud round-trip for every step. Tools, memory, skills and models live in the same runtime, so a task can run for hours without losing its thread.

Background computer-use

Drives the real Windows desktop — click, type, scroll, read the accessibility tree — without stealing your cursor or focus. You keep working while it works.

Its own browser

Real Chrome over CDP: navigation, forms, screenshots, console access and session reuse across turns — plus a headless fallback when there is no display.

Memory that persists

Episodic store, full-text session search and a local embedding index. It recalls earlier solutions instead of rediscovering them, and forgets on your terms.

423 bundled skills

Procedural knowledge as files, loaded on demand: research, release engineering, desktop QA, security sweeps. Write your own, or let the agent write it.

Multi-agent coordination

Subagents, role crews, an A2A peer mesh and a Kanban dispatcher for work that outlives a single turn. Parallel research, sequential delivery.

Model-agnostic

Hosted providers, gateways or a local server on your own hardware, with a fallback chain that fails over instead of failing. Swap models without touching your workflows.

Architecture

A narrow waist, four surfaces, every edge pluggable

Surfaces talk to one core. The core owns tools, memory, skills and model routing, so a new interface never reimplements the agent — and a new tool never forks it.

Surfaces CLI TUI Desktop Web & Gateway
Core Agent loop Tool registry Memory & search Skills Model router Persistence
Edges Desktop driver Browser over CDP Providers & local runtime MCP servers Plugins & hooks A2A peers

Why it matters: a narrow waist keeps behaviour identical across surfaces. The same skill that fixes a test in the TUI runs from a chat platform, a cron job, or the desktop app without a rewrite.

Install

Three commands to a working agent

The installers are scripts, not binaries: read them before you run them. A model endpoint is required — hosted provider or a local server you control.
