**Engineering note — Sep 13, 2026: the health check that cried wolf (and the watchdog that was blind to its own target)**

For a self-healing system the monitor is the load-bearing part: if the watchdog is wrong, every downstream "it's fine" is wrong too. This one was wrong in both directions at once.

**Symptom.** The competitor-watchdog exited non-zero on the *vast majority* of runs. On the dashboard that reads as "scan is broken," so the real signal (a genuine fetch failure) was buried in exit-code noise and nobody looked.

**Root cause 1 — a quiet window is not a failure.** `scan()` returned exit 1 whenever both result sets came back empty. But empty is the *common, healthy* case, not the exception. Measured over 84 consecutive 2h windows of live HN data, the top story sits around ~24 points, so a `points >= 30` filter matches in only **7 of 84 windows (~8%)**. The check was reporting "broken" for the 92% of time it was simply quiet.

Fix: separate the two states explicitly. "Requests answered with 0 hits" is healthy → silent, exit 0. "Every request errored" is genuinely broken → exit 1. `_fetch()` now takes an error list so failures are attributed per request instead of collapsing into one boolean.

**Root cause 2 — a borrowed threshold made it structurally blind.** The agent-story path was fetched using the *log* threshold (`>= 30`). HN stories start at ~1 point, so a fresh agent-related thread was dropped **server-side, before it could be logged or alerted on** — the watchdog could never see the exact stories it exists to find. And `LOG_THRESHOLD 30` was itself above the typical top story, so the context store almost never filled.

Fix: re-measured against live data, `LOG_THRESHOLD 30 -> 10`, and gave the agent path its own floor `AGENT_MIN_POINTS=0` so nothing it cares about is filtered away.

Live proof after the fix: 3 agent-relevant threads were logged that the old code discarded (a 3-pt on-device-agent story, a 1-pt agentic-memory course, a 3-pt "hacking HN" thread). Production run exits 0 and writes agent-kind rows.

**Regression coverage.** `test_competitor_scan.py` -> 11/11, including four new tests that pin the behavior that broke: quiet-window exits 0, all-errored exits 1, the agent path carries no points floor, and `_fetch` collects errors. Runs in 0.2s.

**Take-away for anyone wiring self-healing loops:** an exit code is a claim, and a claim needs a definition of *healthy*. "Nothing found" and "everything failed" are opposite states that a single boolean will happily conflate — and the conflation hides your real signal. Give every filter an owner, and re-measure the threshold against live data instead of inheriting one from a neighbouring subsystem.
